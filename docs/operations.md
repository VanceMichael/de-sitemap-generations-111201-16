# 本地运行说明

先运行单元测试，再执行演示命令。演示从干净临时目录发起真实请求并处理响应，不需要外部站点。
常规导入失败时返回非零退出码，事务中的原文和记录会一起回滚，可保留源文件再次处理。
查询模式只读取当前数据库，不会补采或删除来源数据。需要长期保留证据时，请备份整个数据库。
本地响应服务支持状态码、响应头、文本或 base64 字节正文；未配置路径返回未找到。
每条路径的脚本独立推进，最后一个响应会重复；可借请求记录核对调用顺序。
数据文件的路径均相对项目根目录，修改工作目录前请确认输入和数据库参数。

## 代际遍历运行要点

* `crawl-demo` 依次执行 g1 稳态、滚动窗口（子图 503）、g2 新代际、第二次独立完整视图，
  另含中断恢复、循环引用、并发 CAS 三个专项；报告中的 `incomplete_reasons`
  逐条说明视图为何不可信，`narrative` 给出条目保留/撤下结论。
* 视图完整性判定：全部索引节点获取成功且未触发任何限额。不完整视图不会写入条目生命周期，
  因此夜间同步少条目时不会误标下线。
* 撤下需要连续两次独立完整视图缺席；撤下后又出现的条目会在下一次完整视图中复活。
* 中断恢复：用同一 `--run-id` 再次执行 `crawl` 即可，只会重取未完成节点。
* 并发：同一 run 有互斥锁；子图完成状态按版本号 CAS 提交，旧进程的过期提交返回 stale。
* 模拟站点事件：`status` 覆盖只对当前代际仍引用的资源生效；`references` 可把子文件
  临时替换为索引（制造循环）；`etag` 覆盖模拟窗口期新旧实体标识不一致。
